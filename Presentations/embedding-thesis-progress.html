Database structure

How the database is organized

requirements_combined stores the source rows from both standards, including text, summary, keywords, phase, and embedding.
requirement_mappings should store similarity links between source and target requirements instead of mixing mapping output into the corpus table.
evaluation_logs can later store model, prompt, top-k, answer, and human review results.

Why separate tables?

  • Cleaner schema for vector search.
  • One requirement can map to multiple related controls.
  • Easier evaluation and HITL validation later.
  • Supports thesis reproducibility and experiment logging.

Embeddings explained

What an embedding does in my system

Concept

An embedding converts each requirement text into a numeric vector so similar requirements are positioned closer together in vector space.

Raw text → embedding model → vector
Query text → query embedding
Vector similarity → top matching requirements

Why not keyword search only?

Exact keyword overlapLimited
Semantic similarityHigh
Cross-standard matching potentialStrong
